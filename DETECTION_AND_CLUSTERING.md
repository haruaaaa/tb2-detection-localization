# Кластеризация и детекция робота (TurtleBot 2) по данным LiDAR

В данном документе подробно описана архитектура, математические алгоритмы и параметры настройки системы кластеризации и детекции робота TurtleBot 2 по облаку точек лидара Livox MID-360.

---

## 1. Общая архитектура и поток данных

Система разделена на два независимых ROS 2 узла:

```
 [/livox/lidar] (sensor_msgs/PointCloud2)
        │
        ▼
 ┌────────────────────────────────────────┐
 │      clustering (cluster_node)         │  <-- Пространственная фильтрация
 │   (пакет: tb2-detection-localization)  │      и кластеризация DBSCAN
 └────────────────────────────────────────┘
        │
        ▼ [/livox/lidar/clust] (sensor_msgs/PointCloud2 с полем intensity = cluster_id)
 ┌────────────────────────────────────────┐
 │     o3d_detector (detector)            │  <-- Геометрический фильтр цилиндра,
 │   (пакет: tb2-detection-localization)  │      отсечение стен, Kasa Circle Fit,
 └────────────────────────────────────────┘      трекер с coasting
        │
        ├──► [/detected_robot]      (visualization_msgs/MarkerArray)
        └──► [/detected_robot_pose] (visualization_msgs/MarkerArray)
```

- **Разделение ответственности:**
  - `clustering`: быстрая низкоуровневая обработка облака точек и разделение на связные объекты (кластеры).
  - `detector`: высокоуровневая семантическая классификация кластеров, отсечение стен и столбов, аналитическое вписывание цилиндра и трекинг.

## 2. Нода кластеризации (`clustering/cluster_node.py`)

### 2.1. Особенности системы координат Livox MID-360
Лидар Livox на роботе ориентирован с инверсией оси $Z$ относительно горизонта (наклон вниз):
- Пол находится в диапазоне $z \approx +0.325 \dots +0.34$ м.
- Потолок и верхние перекрытия имеют $z < -0.16$ м.
- Робот TurtleBot 2 на полу находится в диапазоне высот $z \in [-0.15, +0.325]$ м.

### 2.2. Этапы алгоритма в `cluster_node`:
1. **Быстрая бинарная распаковка:**
   - Вместо медленного генератора `pc2.read_points()`, распаковывающего точки по одной в Python-объекты (занимает 50–80 мс на кадр), используется векторизованный `np.frombuffer` (занимает 0.3 мс).
2. **Пространственный фильтр (Region of Interest):**
   - **По высоте:** $z \in [z_{min}, z_{max}] = [-0.35, +0.325]$ м. Отрезает точки пола (шум от колес и отражений) и точки выше потолка, но оставляет верхнюю часть объектов (нужно для детектора, чтобы отличить колонну/стену до потолка от невысокого робота).
   - **По дальности на плоскости XY:** $dist_{xy} \in [0.35, 6.0]$ м. Отрезает детали собственного крепления лидара ($< 0.35$ м) и шум на предельной дистанции ($> 6.0$ м).
3. **Кластеризация DBSCAN (Density-Based Spatial Clustering of Applications with Noise):**
   - Используется реализация из `scikit-learn` с индексацией на KD-дереве.
   - Параметры: `eps=0.14` м (радиус соседства), `min_samples=12` (минимальное число точек для формирования ядра кластера).
   - Шумовые точки (метка `-1`) отбрасываются.
4. **Публикация в `/livox/lidar/clust`:**
   - Формируется PointCloud2 с четырьмя полями: `x, y, z, intensity` (все `FLOAT32`).
   - В поле `intensity` записывается номер кластера ($0.0, 1.0, 2.0, \dots$).
   - Это позволяет RViz2 отображать кластеры радужным спектром при выборе Color Transformer: `Intensity`.

### 2.3. Параметры `cluster_node`

| Параметр | По умолчанию | Описание |
|---|---|---|
| `lidar_topic` | `/livox/lidar` | Входной топик облака точек LiDAR |
| `clust_topic` | `/livox/lidar/clust` | Выходной топик кластеризованного облака |
| `eps` | `0.14` | Радиус соседства точек DBSCAN (в метрах) |
| `min_samples` | `12` | Минимальное число точек в кластере |
| `z_min` | `-0.35` | Верхняя граница по высоте (в системе координат Livox) |
| `z_max` | `0.325` | Нижняя граница по высоте (отсечение пола) |
| `min_dist_xy` | `0.35` | Минимальная дальность (отсечение собственного робота) |
| `max_dist_xy` | `6.0` | Максимальная дальность кластеризации |

## 3. Нода детектора робота (`o3d_detector/detector.py`)

### 3.1. Физическая модель TurtleBot 2
Робот TurtleBot 2 представляет собой трехъярусный цилиндрический корпус:
- Диаметр основания: $D = 0.354$ м (радиус $R \approx 0.177$ м).
- Полная высота: $H \approx 0.35 \dots 0.40$ м.
- Форма при виде сверху: цилиндрическая выпуклая дуга.

### 3.2. Этапы фильтрации кластеров:

#### Фильтр 1: Вертикальные габариты и отсечение стен/колонн
- **Отсечение потолка:** Если верхняя точка кластера $z_{min} < -0.16$ м, объект уходит в потолок (это капитальная стена, дверь или несущая колонна). Робот **никогда** не достигает такой высоты.
- **Отсечение плоских горизонтальных полос стен:** Лидарный луч при отражении от стены дает плоскую горизонтальную полоску с вертикальной толщиной $dz < 0.20$ м. Для робота, имеющего объемный корпус, $dz \in [0.22, 0.42]$ м.

#### Фильтр 2: PCA-анализ формы в плоскости XY (подавление плоских стен)
Для точек кластера в плоскости XY строится матрица ковариации и находятся ее собственные значения:
$$\text{cov} = \frac{1}{N} \sum (p_i - \bar{p})(p_i - \bar{p})^T$$
- Большая полуось: $l_{maj} = 2 \sqrt{\lambda_1}$
- Малая полуось: $l_{min} = 2 \sqrt{\lambda_0}$
- **Критерии отсечения:**
  - $l_{maj} \in [0.16, 0.44]$ м: слишком короткие кластеры ($< 16$ см) — это случайные шумы или тонкие ножки; слишком длинные ($> 44$ см) — это протяженные стены.
  - $l_{min} \ge 0.08$ м: плоские стены имеют толщину в срезе всего $2 \dots 5$ см; цилиндр TurtleBot 2 дает видимую дугу с поперечной глубиной не менее 8 см.
  - Коэффициент вытянутости: $\text{ratio} = l_{maj} / l_{min} \le 2.6$. Стены имеют форму вытянутой полосы с $\text{ratio} > 3 \dots 10$. Цилиндр робота дает округлую компактную дугу ($\text{ratio} \in [1.2, 2.2]$).

#### Фильтр 3: Аналитическое вписывание окружности методом Каса (Kasa Circle Fit)
Вместо ресурсоемких численных оптимизаторов используется замкнутое алгебраическое решение (Kasa method):
Минимизируется функционал:
$$F(x_c, y_c, r) = \sum \left( (x_i - x_c)^2 + (y_i - y_c)^2 - r^2 \right)^2$$
Сводится к линейной системе МНК:
$$\begin{bmatrix} x_i & y_i & 1 \end{bmatrix} \begin{bmatrix} 2 x_c \\ 2 y_c \\ r^2 - x_c^2 - y_c^2 \end{bmatrix} \approx x_i^2 + y_i^2$$
- **Критерии валидации окружности:**
  1. Радиус: $R \in [0.10, 0.23]$ м (TurtleBot 2: $R = 0.177$ м).
  2. Качество аппроксимации: $RMSE = \sqrt{\frac{1}{N}\sum (\text{dist}_i - R)^2} \le 0.048$ м.
  3. Проверка выпуклости (Convexity check): центр вписанной окружности $(x_c, y_c)$ обязательно должен лежать **за** видимой дугой со стороны лидара:
     $$\|(x_c, y_c)\| \ge \|\bar{p}_{arc}\| - 0.04\text{ м}$$
     Это гарантирует, что вогнутые углы стен или коридоров не будут приняты за робота.

#### Фильтр 4: Геометрический скоринг кандидатов
Если в кадре несколько прошедших фильтры объектов, каждому кандидату присваивается штрафной балл:
$$\text{Score} = 3.0 \cdot |R - 0.177| + 4.0 \cdot RMSE + 1.0 \cdot |dz - 0.35|$$
Кандидат с минимальным баллом ближе всего соответствует эталонной модели TurtleBot 2.

### 3.3. Трекер с удержанием (`RobotTracker`)
1. **Экспоненциальное сглаживание (EMA):**
   $$p_t = \alpha \cdot p_{meas} + (1 - \alpha) \cdot p_{t-1}, \quad \alpha = 0.65$$
   Устраняет дрожание координат между кадрами.
2. **Защита от телепортации (`max_jump_dist = 0.8` м):**
   Если ближайший кандидат находится дальше 0.8 м от предыдущей позиции робота (робот не может мгновенно переместиться на метр за 100 мс), трекер игнорирует далекий объект и переходит в режим удержания.
3. **Удержание траектории (`coasting = 6` кадров, 0.6 с):**
   При кратковременном затенении робота препятствием или повороте маркер в RViz плавно удерживается на последней известной позиции, исключая мигание.

## 4. Сводная таблица параметров детектора и их настройка

| Параметр | Значение | Зачем нужен / Как подстраивать |
|---|---|---|
| `tb2_diameter` | `0.354` м | Диаметр корпуса TurtleBot 2 |
| `tb2_radius` | `0.177` м | Радиус цилиндра робота |
| `min_pts` | `14` | Минимальное число точек (для детекции на дистанции до 4–5 м) |
| `min_height_dz` | `0.22` м | Если детектятся горизонтальные полосы стен — увеличить до `0.24` |
| `max_height_dz` | `0.42` м | Если детектятся вертикальные колонны/стены — уменьшить до `0.40` |
| `ceiling_z_threshold` | `-0.16` м | Отсечение объектов, уходящих в потолок (Livox $Z$) |
| `min_wall_length` | `0.16` м | Отсечение мелких точечных отражений и шумов |
| `max_wall_length` | `0.44` м | Максимальная длина хорды дуги робота (стены длиннее этого порога) |
| `min_depth` | `0.08` м | Минимальная глубина дуги. Плоские стены имеют глубину $< 0.05$ м |
| `max_aspect_ratio` | `2.6` | Если детектятся вытянутые участки стен — уменьшить до `2.2` |
| `min_radius` | `0.10` м | Нижняя граница радиуса вписанной окружности |
| `max_radius` | `0.23` м | Верхняя граница радиуса (отсекает дуги большего радиуса) |
| `max_circle_rmse` | `0.048` м | Допустимая шероховатость/ошибка аппроксимации дуги окружностью |
| `max_coasting_frames`| `6` кадров | Время удержания маркера при потере видимости (~0.6 сек) |
| `max_jump_dist` | `0.8` м | Максимальный скачок робота между кадрами (защита от прыжков на стены) |

## 5. Инструкция по сборке, запуску и визуализации

### Сборка пакетов в Docker:
```bash
cd /root/ws/src/tb2-detection-localization
colcon build --packages-select clustering o3d_detector --symlink-install
source /root/ws/src/tb2-detection-localization/install/setup.bash
```

### Запуск узлов:
1. **Кластеризация:**
   ```bash
   ros2 run clustering cluster_node
   ```
2. **Детектор робота:**
   ```bash
   ros2 run o3d_detector detector
   ```
3. **Воспроизведение росбага:**
   ```bash
   ros2 bag play /root/ws/HSL26-ros2_bags/rosbag2_2026_06_27-18_43-mov_01
   ```

### Визуализация в RViz2:
- **Облако кластеров:** Добавить дисплей `PointCloud2`:
  - Topic: `/livox/lidar/clust`
  - Color Transformer: `Intensity` (каждый кластер будет окрашен в свой цвет радуги).
- **Обнаруженный робот:** Добавить дисплей `MarkerArray`:
  - Topic: `/detected_robot` (или `/detected_robot_pose`).
  - Отображается зеленый цилиндр габаритов TurtleBot 2 и текстовая метка с дистанцией до робота.
